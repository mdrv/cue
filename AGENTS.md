# AGENTS.md

Guidance for AI agents (Claude, Cursor, Copilot, opencode, etc.) working on Cue.

## Project invariants (do not violate)

1. **Pure TypeScript on Bun.** No Node.js, no webpack, no vite, no frontend framework.
2. **Vanilla frontend, no build step.** The prompter is a single HTML string with inline CSS/JS. Served by `Bun.file`. The prompter UI renders markdown client-side; `Bun.markdown` is only available server-side.
3. **Config is TypeScript, not YAML/TOML.** `defineConfig()` helper in `cue.ts`.
4. **Transcript files are `.ts` files.** They export `transcript` — a bare array or `{meta, cues}` object.
5. **Speaker routing is declarative.** Config maps names to columns; transcript tags cues; frontend renders. Three clean layers.
6. **`transcript/` and `errors/` are pure modules.** No I/O except `parseTranscriptFile` (which uses dynamic import). No async in schema/estimate.
7. **CLI goes through the public `src/index.ts` API.** Never import internal modules from `cli/`.
8. **LogTape core is `@logtape/logtape`** — NOT `@logtape/tapelog` or any other package.
9. **No code comments** unless the user explicitly requests them.
10. **Markdown rendering is sanitized.** `renderMarkdown` neutralizes raw HTML, strips event handlers, and restricts link/image URLs to safe schemes. Keep it that way.

## Stack

| Concern       | Choice                                                                            |
| ------------- | --------------------------------------------------------------------------------- |
| Runtime       | Bun (latest, ^1.4.4)                                                              |
| Language      | TypeScript strict (typescript@^7 for editor parity), `allowImportingTsExtensions` |
| CLI framework | `@crustjs/core` + `@crustjs/extensions`                                           |
| HTTP server   | `Bun.serve` (built-in)                                                            |
| File watcher  | `node:fs.watch` (`Bun.watch` was removed in the Bun 1.4 Rust rewrite)             |
| Markdown      | `Bun.markdown.html()` + `HTMLRewriter` sanitizer (server-side API only)           |
| Logging       | `@logtape/logtape` (NOT `@logtape/tapelog`)                                       |
| Hooks         | `prek` via `prek.toml`, generated by `lhg` (`.lhg/config.toml`)                   |
| Formatter     | `dprint` (config in `dprint.jsonc`)                                               |
| Test runner   | `bun test`                                                                        |
| Validation    | `zod`                                                                             |

## Code style (enforced by `dprint.jsonc`)

- **Tab** indentation
- **Single** quotes
- **No** semicolons (`semiColons: "asi"`)
- `camelCase.ts` filenames, one primary export per file
- `PascalCase` types (no `I` prefix)
- `camelCase` functions, verb-first (`parseTranscriptFile`, not `transcriptParse`)
- `SCREAMING_SNAKE_CASE` for constants/enum-like values
- `kebab-case` for CLI subcommands (`cue check`)
- **NO code comments** unless the user explicitly requests them

## Commands

```sh
bun test                       # run tests
bun check                      # typecheck (never emit; respects tsconfig.json)
bun src/cli/index.ts <cmd>     # run CLI from source
dprint fmt                     # format all files
dprint check                   # verify formatting without writing
bun install                    # install deps
```

Never add a package.json script named `check` — it shadows the built-in `bun check` command.

## Workflow

1. **Respect layering** — `cli/` → `config/`/`transcript/` → `server/` → `frontend/`; `transcript/` and `errors/` stay pure.
2. **Prototype fast, test thoroughly.** Working end-to-end slice first, tests at the end of each milestone.
3. **Run `dprint fmt` and `bun check`** before considering any code change complete.
4. **Never commit** unless explicitly asked.

## Common pitfalls

- Reaching for `@logtape/tapelog` — the core package is **`@logtape/logtape`**.
- Adding a framework (React, Vue, Svelte) to the frontend — it must stay vanilla.
- Adding a build step (webpack, vite) for the frontend — not allowed.
- Writing YAML or TOML config — config is TypeScript only.
- Treating speaker routing as implicit — it must be declarative in config.
- Adding semicolons or double quotes — formatter enforces ASI and single quotes.
- Adding code comments — only when explicitly requested.
- Using `Bun.watch` — removed in Bun 1.4; use `node:fs.watch`.
- Calling `Bun.markdown` from frontend code — it is a server-side API; the browser prompter renders markdown with its own inline code (`src/frontend/app.js`).
- `@crustjs/plugins` no longer exists — help/version/completion live in `@crustjs/extensions` as Extensions (`.extend()`) since core 0.5.
