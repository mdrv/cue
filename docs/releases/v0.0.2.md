## v0.0.2

Polish release focused on the prompter being usable for real rehearsal. Cues now render inline markdown, a new `anchor` option mirrors the layout so the focus can pin to the bottom and content scrolls down, font size and theme choice survive hot-reload via `localStorage`, a thin progress bar shows position, the config file itself is watched, `cue list` summarizes a transcript richer than `check`, and validation errors point at the offending cue with a preview of its text.

### Added

**Frontend** (`src/frontend/`)

- `renderInlineMarkdown` — new `src/frontend/markdown.ts` module (HTML-escape → code-span placeholders → links → bold → italic → restore). Mirrored inline in `app.js` so the browser stays build-free.
- Inline markdown subset: `**bold**`, `*italic*`, `` `code` ``, `[label](url)`.
- URL safety filter — `javascript:` and `data:` schemes are stripped; relative URLs (`/path`, `./x`, `#anchor`) are allowed.
- `markdown: boolean` on `CueConfig` (default `true`). Set `markdown: false` to render cues as plain text.
- `anchor: 'top' | 'bottom'` on `CueConfig` (default `'top'`). `'bottom'` mirrors the layout: focus pins to the bottom of the stage and content scrolls down as you advance. Implemented via a `.bottom` class on each column (`flex-direction: column-reverse`); DOM order is unchanged.
- CSS for `.cue code`, `.cue em`, `.cue strong`, `.cue a`.
- Progress bar — `<div id="progressbar"><div id="progressFill"></div></div>` between stage and help. Width tracks `index / total * 100%` with a `.2s` transition.
- Font size persistence — `+`/`-` keys save to `localStorage` under `cue:<encoded-title>:font`.
- Theme persistence — `T` key saves dark/light choice to `cue:<encoded-title>:light`.
- Hot-reload aware — `render()` reads `config.duet || meta.duet` and `config.markdown !== false` on every render so a config reload takes effect immediately.

**Server** (`src/server/`)

- Config hot-reload — `ServeOptions` accepts `configPath` and `reloadConfig: () => Promise<CueConfig>`. The config file is watched with the same 150ms debounce as the transcript. On change, the new config is loaded, flag-merged again, and broadcast as `{ config }` on the `reload` event.
- Multiple watchers tracked in a local `const watchers: FSWatcher[]`; `stop()` closes all of them.

**CLI** (`src/cli/`)

- `cue list <file>` — new command. Plain output prints `✓ <file> "<title>" — N cues, speakers: ...`, then one numbered row per cue (`N. [speaker] (Xms) <preview>`), then `Total: Xms timed, N manual cue(s)`. `--json` emits `{ ok, file, meta, cues, summary }`. `--wpm N` shows `~Xms` estimates for cues that lack a duration.
- `withErrors` higher-order helper wraps every `.run()` callback so CueError instances are formatted uniformly: `cue: <message>`, then `- <issue>` per Zod issue, then `key: value` for other context fields.
- `reportError` exported from `src/cli/shared.ts` for the same formatting in setup-phase errors.
- Discovery: CrustJS's `execute()` swallows errors thrown from `.run()` callbacks and never re-propagates them to the top-level await. `withErrors` works around this by formatting + `process.exit(1)` inside the handler.
- `src/cli/play.ts` factored `buildConfig` so the same flag-merge logic is reused for initial config and hot-reload.

**Transcript** (`src/transcript/`)

- `formatIssue(path, message, raw)` — Zod paths that resolve to a cue index are rendered as `cue #N "<preview>" — <field>: <message>` with up to 60 chars of whitespace-normalized text. Other paths fall back to `<path>: <message>`.
- "No transcript export" error now includes `hint: 'Add`export const transcript = [...]`...'` in its context.

**Public API** (`src/index.ts`)

- Re-exports `renderInlineMarkdown` from `src/frontend/markdown.ts`.

**Tests** (`tests/`)

- `tests/markdown.test.ts` (7 new tests): HTML escaping, bold + italic, inline code (protected from later transforms), safe links, blocked `javascript:`/`data:` schemes, relative URLs allowed, plain text untouched.
- Total: 20 tests across `schema.test.ts` (7), `estimate.test.ts` (3), `load.test.ts` (3), `markdown.test.ts` (7). All pass.

### Changed

- `package.json` version bumped `0.0.1` → `0.0.2`.
- `app.js` no longer caches `duet` and `useMarkdown` at module top-level — both are read inside `render()`/`renderText()` so hot-reloaded config takes effect.
- `src/cli/shared.ts` usage string now reads `cue <file> | cue check <file> | cue list <file> | cue init`.
- `src/cli/index.ts` now `await`s `main()` instead of firing it void.

### Fixed

- BUG-002 — Frontend font size now persists across hot-reload via `localStorage` (per-transcript key). Theme choice (`T` key) is also persisted.
- SSE 500 error on `GET /events` — the `streamCancel` variable was referenced inside the `ReadableStream` `start()` callback before its declaration, hitting a temporal-dead-zone error. The declaration was moved above the `ReadableStream` constructor.

### Known issues

- BUG-001 — Hot-reload re-fetch race on rapid (sub-150ms) edits still possible.
- BUG-003 — Firefox `EventSource` reconnect may flicker.
- BUG-004 (new) — Inline-code link regex uses `[^)\s]+`, so URLs containing literal `)` characters are truncated. Workaround: percent-encode `)` as `%29`.
- BUG-005 (new) — Markdown rendering is inline-only. Block-level constructs (headings, lists, blockquotes) are deferred to v0.1.0.
- BUG-006 (new) — `cue list --json` does not include estimated durations unless `--wpm` is passed.

### Not in v0.0.2 (deferred)

- Image cue type.
- Countdown timer.
- Export command (`cue export`).
- Browser tests (Playwright) — see v0.1.0 roadmap.
- Mobile-responsive layout.
- Plugin system.
