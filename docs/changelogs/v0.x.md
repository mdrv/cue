## v0.2.0 — Typed frontend

The prompter and remote pages are now served from typed TypeScript modules; `src/frontend/app.js` is gone and the whole frontend is covered by `bun check`.

- **Module split**: the prompter entry `app.ts` composes `state`, `layout`, `render`, `renderWindow`, `controls`, `sync`, `dom`, `types`, and `inlineMarkdown` modules; the remote page's inline template-string script became the typed `remoteMain.ts` (transpiled at serve time with `Bun.Transpiler`). Shared `ClientConfig`/`ClientData` types moved to `frontend/types.ts` and are re-exported from the public API.
- **Serve-time bundling**: `Bun.build` (target browser, in memory, no artifacts) assembles the prompter bundle on server start — the served page is still a single HTML string with inline JS. AGENTS.md invariant #2 now records this explicitly.
- **Riding fixes**: the state-pull guard no longer stays latched after a sync POST resolves (the debounce timer clears inside its callback), and config hot-reloads now refresh cached section boundaries so the section bar tracks new sections immediately.
- **Sanitizer tests**: new `tests/markdown.test.ts` locks the client-side inline markdown renderer — HTML escaping, the safe-URL policy, and the `markdown: false` escape-only mode.

## v0.1.0 — Platform refresh

Full modernization pass. No transcript-author-visible behavior changes except where noted.

- **Runtime**: Bun ^1.4.4 (Rust rewrite); `@types/bun` pinned to match. `Bun.watch` no longer exists in Bun 1.4 — the prompter stays on `node:fs.watch`.
- **Type checking**: `bun check` (Bun's TS7-ported checker) replaces `tsc --noEmit`; typescript@^7.0.2 kept for editor parity; tsconfig `types` switched to `["bun"]`.
- **CLI**: rewritten for @crustjs/core 0.5 (Contexts & Extensions). Global flags are a provided Context; help/version come from `@crustjs/extensions`; deprecated `@crustjs/plugins` removed; Ctrl-C cancellation now flows through CrustJS's signal.
- **Inline config**: transcript files may export `config` alongside `transcript` (partial `CueConfig`, plain object or `defineConfig`). Resolution is layered — defaults ← config file ← `transcript.meta` ← inline config ← CLI flags — with deep merge (theme per color, speakers per entry). `cue check` validates and reports it; hot-reload re-applies it on transcript edits.
- **Layout control**: `anchor` is now a 2-axis pin (`'top-left'` … `'bottom-right'`, 9 combos; single words like `'top'`/`'left'` accepted as shorthands). New `flow: 'horizontal'` renders the solo column as a side-scrolling strip; new `reverse` flips the entry edge so the next line arrives from above (vertical) or from the left (horizontal) — e.g. `flow: 'horizontal', reverse: true, anchor: 'top-left'` puts the focus line at the top-left with new lines sliding in from the right. Default anchor changed from `'top'` to `'center'`; `anchor` now genuinely pins focus (previously it only swapped section-bar ordering and always centered). `flow`/`reverse` apply to solo mode; duet stays two vertical columns.
- **Remote control**: the server now binds `0.0.0.0` and logs LAN URLs on start. `GET /remote` serves a touch page (tap zones, play/pause, cue drawer, look-ahead) for driving the prompter from another device. New server-authoritative presenter state `{index, playing}`: `POST /api/remote` accepts `{action: next | prev | goto | play | pause | restart | sync}` (`sync` reports the prompter's own position), `GET /api/state` returns the current state, and `/events` broadcasts it alongside transcript/config payloads. State flows in both directions, so phone and prompter stay in sync.
- **Look-around control**: new `lookBehind` (default 1) and `lookAhead` (default 2) config fields set how many dimmed cues precede and follow the focus line, in solo and duet columns alike — `lookBehind: 0` shows no previous lines.
- **Chrome placement & touch zones**: new `chrome: 'top' | 'bottom'` (default `top`) moves the title bar and section indicator to the bottom edge of the screen. The section bar follows `chrome` only — `anchor` no longer moves it. On the prompter, tapping the leftmost 20% of the stage steps back; tapping anywhere else advances — so touch-only setups can go backwards too.
- **Cue timer line**: while playing, a thin accent bar grows under the current line over its `duration` — a visual countdown to the next line, right where you're looking.
- **Content width**: new `contentWidth` config (px, 0 = auto `60ch`) caps the reading column; `W−` / `W+` buttons in the prompter control bar adjust it live and persist per device.
- **iPhone/mobile fixes**: `reverse` no longer uses `column-reverse` (unreliable overflow scrolling in Safari/iOS) — the render window is built in reversed order instead, so `scrollIntoView` pinning works on every advance; while playing, the focus jump scrolls instantly instead of smoothly, so the cue-timer bar starts in sync with the new line; the fullscreen control-bar button hides itself on browsers without the Fullscreen API (iOS Safari); the touch control bar follows `chrome` (top or bottom). The layout tracks the dynamic viewport (`100dvh`) and focus pinning insets by the stage padding (`scroll-padding`), so the bottom-anchored line and its timer bar stay fully visible on iOS Safari; the timer bar animates reliably from 0 (style flush before the transition starts) and no longer restarts when the prompter receives its own state echo.
- **State reconciliation**: the prompter and remote pull the authoritative presenter state from `/api/state` whenever their SSE connection re-establishes or the tab becomes visible again — a phone that suspended its tab and missed a broadcast no longer shows a stale position; the show also auto-pauses when it reaches the end.
- **Fixed (hot reload)**: two bugs broke live editing. `node:fs.watch` on the file path died silently after the first atomic-replace save (every editor's default on Linux), so Cue now watches the parent directory and filters by filename; and dynamic `import()` handed back the cached module forever, so reloads now go through `require()` with `require.cache` invalidation (keyed by `require.resolve`). The config-file watcher had the same cache bug — both paths fixed and verified live.
- **Fixed**: `open: false` in config files was ignored (the `--open` flag carried a hard default); the flag now only overrides when explicitly passed.
- **Markdown (breaking)**: `renderInlineMarkdown` removed. The public API is now `renderMarkdown` — async, full GFM via `Bun.markdown.html()`, sanitized with HTMLRewriter (raw HTML neutralized, event handlers stripped, URLs scheme-restricted, safe links open in a new tab). The prompter UI still renders markdown client-side.
- **Dependencies**: @logtape/* ^2.4.2, zod ^4.6.7.
- **Repo**: hooks migrated from lefthook to prek (`prek.toml`, generated by lhg); MIT LICENSE added; docs moved out of the repo.
